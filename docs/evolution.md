## 感受词，翻译成参数

这个产品的很多决定，最初都是一句感受；落地时，它们都变成了一个可以验收的数：

| 感受 | 参数 |
|---|---|
| 浮光要再快一点 | 自然速度 +16.4%（`MOTION.speedScale = 1.164`） |
| 入口的角度不对 | 从 40° 改为 23.5°，整体缩小 17.5% |
| 邀请不该一直挂着 | FSD 按钮 4.25 秒不点就淡出 |
| 阵容换得太慢 | 重抽从 18 秒收窄到 11.5 秒 |
| 上面要撑起来，但不是越高越好 | 上方 38% 是平台而不是坡：整体 ×2，边界余弦羽化 48 px；纵向拉开的奖励封顶 +35% |
| 近一点可以被偶尔容忍 | 近距惩罚 0.8，低于远距 1.6 和沙漠 1.8 |
| 编号要「不仔细看就几乎看不见」 | 透明度 0.45，8.5 px，−7° |
| 「再亮 2.35 个点」 | 落款以 HSL 亮度 +7 为基准重烤，最终 `#CBAE60` |
| 比例数字要有性格 | 18 px、字重 520、斜体 |

## 走过的弯路

这些错误都被找到、修好，并且变成了之后每一版的检查项。

| 问题 | 真因 | 留下的规则 |
|---|---|---|
| 主页在宿主里反复崩溃，本机浏览器永远看不见 | 宿主高频重发就绪事件，初始化雪崩 | 放弃猜测，先上「黑匣子」记录；初始化必须幂等 |
| 3.1 版无法导入 | 包内清单的版本号不是 SemVer；只改 ZIP 文件名没用 | 交付前校验实际 ZIP 的清单、路径与 CRC，而不只是源文件 |
| 力度调到 24，自然碰撞仍然散不开 | 特效掩盖了物理：有折光，没有分离 | 视觉反馈、位置修正与动量传递分开检查 |
| 落位「太簇一块儿」 | 远距惩罚与沙漠惩罚在同一个候选上互相乘杀 | 多因子调参，先画出因子相乘之后的权重曲线 |
| 「70% 好像没有兑现」 | 判定没错，瓶颈在进圈的机会 | 概率类问题先量机会率，再量触发率 |
| 落款在真机上隐身 | `file://` 下 `mask-image` 被跨源校验拦截 | 交付物在 http 与 `file://` 两种打开方式下各验一次 |
| 力度分布只剩 138 次，同期碰撞 824 次 | 改分档时整张表被清零 | 凡是改变量纲或档位，默认配迁移函数 |

## 一直没变的原则

- **轻盈不等于不可见。** 关键操作要找得到；玻璃负责组织，而不是让每个按钮各自发亮。
- **关键时刻要被感到。** 碰撞在接触的那一帧弹开；邂逅要有足够的机会发生。
- **自动行为不冒充人的选择。** 驾驶与邂逅不写概率、不计交互。
- **口径先于功能。** 图表上线之前，先定义每个数字代表什么；存储决策之前，先算清楚成本。
- **相对优于绝对。** 凡是会随长期使用「通胀」的量，都用相对量呈现。
- **数据的不变量就是产品的信用。** 迁移保总量、写入守形状、复制先自检、旧数据宁粗不丢。
- **名字是设计的一部分。** 「备份文本」而不是「存档串」；「落子与星座」；「念起，光行」。
