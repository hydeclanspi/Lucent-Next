# Maintaining Lucent

Product: **Lucent · 灵感台**. The floating-lens engine is **Lueurs** (小浮光, codename 代号：交互). Repository `lucent`, author **hydeclanspi**. The native package is the Aira (HarmonyOS) 5.0 build; this repository is its web edition.

## Details that have caused mistakes

1. **Search dispatch belongs after the animation.** Enter and the arrow share one form submission. Clear the live and default input values, respect IME composition, prevent duplicates, and verify the return from a navigation.
2. **Blue comes from theme injection.** The original CSS has an orange fallback; the browser layer supplies `#0A59F7`. The warm name gradient and engine outlines are intentional.
3. **Wallpaper is not theme.** The Light/Dark wallpaper and the light/dark interface are independent. The default framing is the device's: the whole bitmap, covering the wallpaper layer and centred, so the web edition at 3:2 shows exactly what the MatePad shows. The London bitmap includes a device dock at its lower edge, which on the device sits under Aira's toolbar. Do not rewrite the bitmaps.
4. **Three kinds of surface.** The profile editor is `.edit-root`, product sheets live in `#sheetRoot`, browser-layer panels are `.ab-overlay`. Tests must target the right one.
5. **Names and keys.** Display names are Lucent / 灵感台 / Lueurs. Storage keys keep the `aira-profile-card:` prefix and environment variables keep `AIRA_`: they are compatibility keys, not branding.
6. **Private browsing is a demonstration.** It only stops the local history record; it is not a real incognito mode, and the example history is not anyone's real history.
7. **Relative paths only.** The site must keep working under a repository subpath.
8. **Docs anchor to source lines.** `docs/*.md` and `docs/en/*.md` link to `src/assets/…#Lnn`. When code moves, search for `#L` and update both languages.
9. **Documented numbers are test-backed.** Changing an engine constant means updating the test that pins it, the figure that draws it, and both language versions of the docs.
10. **Short landscape screens.** On wide screens the card is centred vertically, so a short screen lifts it until the history tag meets the top bar. `guardCardClearance` in `app.js` lowers the card just enough to keep 16 px clear. Do not move the tag itself, and keep the tablet layout untouched (card top 304 px at 1560×1040, set in HarmonyOS Sans, plus the 39 px status bar of the web edition: 343 px): the browser suite checks both.
11. **Immersive full screen is web-only.** Out of full screen, every real click (except on the prompt) asks for it; Esc leaves, and the next click asks again. A page cannot tell a fresh open from a reopened tab, so nothing is remembered. Captures and tests opt out with `sessionStorage['lucent:immersive:off']`. Out of full screen on a large screen, a pill (`.lx-immersive-hint`) says full screen is best and offers a button; its × hides it for the visit. In full screen, `.lx-demo-note` in the lower left says the web edition is a simulation. Every browser-layer panel carries `.ab-demo-note` above its header rule. It is armed only on large screens and only by a real click. The browser suite and the capture scripts start with it off, so it never interferes with them; immersive mode has its own check.
12. **Type is the device's.** Every surface uses `var(--sans)` (HarmonyOS Sans, then the web edition's copy, Lucent Sans) or `var(--mono)` (Noto Sans Mono, as Lucent Mono); there is no serif and no system stack of its own. `src/fonts/` is generated by `scripts/web-fonts.py`: run it again when the product gains words with new characters, so they join the core slice instead of fetching a rare one. The Chinese is HarmonyOS Sans SC 1.0 in static cuts, mapped to the weights the page asks for (600 is drawn by Medium, as it measures on the device); the Latin is the device's variable HarmonyOS Sans 2.04.
13. **The web edition wears the device's chrome.** On screens at least 900 × 740 the browser layer draws HarmonyOS's status bar (and sets `--safe-t: 39px`, the device's inset) and, only in full screen (`<html data-immersive="full">`, set by `immersive.js`), Aira's toolbar and the gesture bar, measured from a screenshot of the MatePad; the status icons are traced from it. Each visit opens on six Lueurs and a Random wallpaper at Light 99 : 1 (`showcaseDefaults` in `browser-bridge.js`).

## Documentation media

**Figures** are drawn from the engine's own functions, so they cannot drift from the code:

```sh
AIRA_BROWSER_PATH=/path/to/chromium node scripts/figures.mjs            # all nine
node scripts/figures.mjs architecture gestures                        # or some of them
```

They are written to `docs/figures/<name>.{zh,en}.png`. `architecture` is the layered product map; `gestures` annotates `showcase/media/hero.jpg`, so re-render it after a new hero. The app icon and the social preview are rendered the same way: `node scripts/icon.mjs` and `node scripts/og.mjs` (the preview also follows a new hero).

**Screens and animations** are rendered, not screen-recorded (one exception, `search-aura.webp`, is cut from the device; see the table): the product runs on a fake clock and a frozen CSS timeline, and every frame is its exact state at an exact virtual time ([`scripts/capture/recorder.cjs`](../scripts/capture/recorder.cjs)).

```sh
npm run build
node scripts/capture/scenes.cjs lueurs motion random simulation focus glass atelier   # a few minutes each
node scripts/capture/scenes.cjs week chronicle                       # a simulated week, then the panels
```

Frames and stills land in the ignored `verification/capture/`. `CAPTURE_QUICK=1` runs a short smoke version of every scene. To encode:

**The film** is rendered the same way, one exact frame at a time: the page is never played, only seeked.

```sh
python3 scripts/film-score.py                                        # showcase/film/score.webm and score.m4a (numpy, scipy, ffmpeg)
python3 scripts/film-score.py --list                                 # the versions of the score; --style <name> renders one, --all --out <dir> every one
npm run build
AIRA_BROWSER_PATH=/path/to/chromium node scripts/film.mjs              # Lucent-Film.mp4, 1440p60 H.264 with the score
node scripts/film.mjs --preview                                      # half size, 24 fps, into verification/film/
node scripts/film.mjs --from 20 --to 32 --out verification/film/part.mp4
```

Two pages render in parallel (`--workers`) at 2560 × 1440 (`--scale 1` for 1080p). A page that follows the camera into the screen holds on to memory for every scale it passes through, so when memory in use passes 65 % (`--recycle-at`) every page is replaced by a fresh one; the film is a function of time, so the frames are unchanged. On two cores with 6 GB the full film takes about an hour and a half (49 MB); it was rendered in three silent parts of about half an hour each (`--from`, `--to`, `--mute`), joined with ffmpeg's concat demuxer and laid over the score. The score reads the scene marks from `showcase/film/film.js`, and the film's form from `scripts/score/form.py`: every section with an energy from 0 to 5, which sets how many instruments play and where the faders sit. So after retiming a scene, compose it again (about a minute; `--report score.png` draws its spectrogram and its loudness against the form). It is synthesized from nothing but code — pianos, mallets, plucked and bowed strings, voices, brass, basses and leads, drums and percussion from physical and subtractive models, a desk with buses, sidechains, rooms and a master — and mastered to −16 LUFS with true peaks under −1 dBTP; every run checks the harmony and prints the loudness of each section against the energy it was written for. After changing any words in `showcase/film/`, run `python3 scripts/film-fonts.py` (needs `fonttools` and `brotli`) so the bundled subsets cover them.

**The on-device recording** (`showcase/device/lucent-on-device.mp4`, played by the page at `/device/`) is an edit of two screen recordings made on the MatePad Edge: one of 1:47, from the search to the backup, and one of 0:26, from the search box as it was to the gold silk of 5.1.3 and the folded card. The recordings are not kept in the repository.

```sh
node scripts/film-media.mjs device                              # the cover at 2x, with and without its words
python3 scripts/device-edit.py SVID_20261019_173443_1.mp4 SVID_20261020_131207_1.mp4      # the edit, its music, the poster
python3 scripts/device-edit.py A.mp4 B.mp4 --head showcase/device/lucent-on-device.mp4    # recompose only the second recording
python3 scripts/device-edit.py A.mp4 B.mp4 --stills 3.3 7.3 40.2   # a few frames to check
```

It opens on the cover the README shows (`design/covers/on-device-frame.html`, whose `?bare` variant leaves the screen empty): the cover's words leave and the recording comes up in the device's 3:2 screen. The device keeps its size, with only a slight lean in, so its name stays under it; the search plays at its own pace, the line of light and the page it opens included, and the quiet stretches run faster with their speed marked above the device; the recorder's own indicator is filled in from around it. After the backup the second recording takes over and the camera goes into the screen, framing what the README's `search-aura.webp` frames: the search box, a tap on ✧ 理, the loop switched on at the panel's top right, the silk round the box, a query typed, and the whole card folding into focus as the camera leaves; its taps are marked with rings, and the speed mark stays in frame. Its music is the film's score from the silence before the residents to the end, rendered again with its sound effects muted, and the cut follows its sections; the score itself is cut at bar lines to fit (`MUSIC`): a bar less where the wallpaper panel waits, and at the finale it goes back ten seconds, so the quiet passage plays under the silk and the finale lands as the card folds. The cut, the speeds, the camera and the music's joins are tables at the top of the script. `--head` takes the first recording's part from an earlier render (the frames in `HEAD`) rather than composing it again, which is how the end was re-cut for 5.1.3.

The browser suite writes its own review captures to ignored `verification/screenshots/`; they are evidence for a run, not documentation.

## Work sequence

Inspect `git status` before editing. Make the smallest change that fits the requested behaviour, build, then run the relevant checks: `npm run check` and `npm test` always; `npm run test:browser` for bridge, navigation or persistence changes. The browser suite stubs external pages, so it never sends a query to a search provider.

Before a release run all four (check, unit tests, build, browser suite), review desktop and mobile in both themes, and keep [VERIFICATION.md](VERIFICATION.md) explicit about what was actually checked.

Before making the repository public, review the profile details and the artwork sources across the whole reachable history. No redistribution licence is granted for the artwork; see [ASSETS.md](ASSETS.md).
