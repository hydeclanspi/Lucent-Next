Outgoing provider pages are intercepted: the tests verify the real destination URL and the timing of navigation without sending a query to any search provider. They say nothing about Google's or Bing's own rendering, regional availability or uptime.

## What this does not cover

- **Feel on a touchscreen.** The tests prove the rules; the feel of the Lueurs under a finger was tuned on the device across 111 versions, and is not re-measured here.
- **The device packages.** All five ZIPs in `product-finale/` are kept byte for byte and their digests are checked; the web edition itself was accepted in the browser, beside screenshots of the device.
- **The local shelf's pickers.** Choosing folders and files through ArkWeb's file manager, re-granting access and opening pages from Aira depend on the device and its browser; they were tried on the MatePad Edge build by build, from 5.2.0 to 5.9.4, and are not exercised here. The 5.9.7 persistent-grant path was checked in the source and built web edition, not with a fresh MatePad import. 6.0.1's `data:` opening was checked in a simulated Aira host, not yet on the MatePad; whether ArkWeb displays a PDF given as a `data:` address is not known.
- **The film in real time.** The suite seeks the film to fixed moments. Smooth real-time playback in a browser depends on the viewer's graphics hardware; `Lucent-Film.mp4` at the repository root is the reference render.
- **Other browsers.** This run used Chromium; the CI workflow runs the same suites on Linux for every push and pull request. See the repository's Actions page for its current status.

The browser suite writes review screenshots and a JSON result file to the ignored `verification/` folder.
